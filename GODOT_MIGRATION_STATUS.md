# Godot migration status

The browser game remains the canonical feature and content baseline. The repository also contains an active native Godot 4 project under `godot/`, with its own scenes, gameplay engines, data catalogs, save repository, and automated native tests under `tests/godot/`.

The native port is **in progress, not feature-complete**.

The native Godot project now also contains a persistent regional world-event engine and exploration UI: deterministic regional templates, cooldowns and expiry, accepted kill/elite/boss/discovery objectives, timed regional defense, faction reputation changes, the two-stage Ash Nomad event campaign, and one-time reward claims. The event clock is persisted with fractional spawn deadlines and is advanced from the native runtime. Dedicated engine tests are included in the unified `.github/workflows/ci.yml` workflow, in the `Validate native Godot project` job; this addition must not be considered runtime-verified until that job passes. Camp crafting mirrors the browser order lifecycle: queued jobs persist with millisecond `readyAt` timestamps, ready rewards are claimed at the alchemist/blacksmith, and inventory-capacity failures leave orders pending. The native merchant mirrors the browser stock pools: five randomly selected common goods in the village, and three common plus two rare goods for wandering merchants. Wandering merchants spawn deterministically at a 16% per-region-visit chance in eligible non-safe exploration regions, appear as clickable map/NPC entries, and open the rare-stock shop. Tests cover spawn probability vectors, deterministic placement, excluded areas, stock pools, item definitions, prices, and stock composition. Recent work has hardened save validation and progression for the Rift and Tower, and expanded native encounter/combat parity.

The browser implementation must remain intact while remaining feature, save-schema, combat, map, UI, and rendering parity is audited. Known remaining parity areas include full legacy-save compatibility and lossless round-tripping, faction bonus application in all relevant gameplay paths, chronicles parity, visual/UI parity, and NPC behavior beyond the currently implemented wandering merchant. These are audit targets, not claims that each area is wholly absent.

## Verification

Browser and native validation now run through the single `.github/workflows/ci.yml` workflow. The browser checks run in `Verify (syntax + imports + smoke load)`; Godot project import, native regression scripts, and main-scene smoke boot run in `Validate native Godot project`. The separate `godot-ci.yml` validation workflow was removed to avoid duplicate CI pipelines; deployment and browser-baseline import workflows remain separate because they perform non-validation tasks.

Use the GitHub Actions workflow as the verification source of truth. Do not describe native tests, browser checks, or deployment as passing until the corresponding workflow run for the current commit SHA has completed successfully. A queued or in-progress run is not a pass.
