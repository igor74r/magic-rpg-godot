# Godot migration status

The browser game remains the canonical feature and content baseline. The repository also contains an active native Godot 4 project under `godot/`, with its own scenes, gameplay engines, data catalogs, save repository, and automated native tests under `tests/godot/`.

The native port is **in progress, not feature-complete**.

The native Godot project now also contains a persistent regional world-event engine and exploration UI: deterministic regional templates, cooldowns and expiry, accepted kill/elite/boss/discovery objectives, timed regional defense, faction reputation changes, the two-stage Ash Nomad event campaign, and one-time reward claims. The event clock is persisted with fractional spawn deadlines and is advanced from the native runtime. Dedicated engine tests are included in the unified `.github/workflows/ci.yml` workflow, in the `Validate native Godot project` job; this addition must not be considered runtime-verified until that job passes. Camp crafting mirrors the browser order lifecycle: queued jobs persist with millisecond `readyAt` timestamps, ready rewards are claimed at the alchemist/blacksmith, and inventory-capacity failures leave orders pending. The native merchant mirrors the browser stock pools: five randomly selected common goods in the village, and three common plus two rare goods for wandering merchants. Wandering merchants spawn deterministically at a 16% per-region-visit chance in eligible non-safe exploration regions, appear as clickable map/NPC entries, and open the rare-stock shop. Tests cover spawn probability vectors, deterministic placement, excluded areas, stock pools, item definitions, prices, and stock composition. Recent work has hardened save validation and progression for the Rift and Tower, and expanded native encounter/combat parity. Campaign kill-counter normalization now accepts finite non-negative safe integral floats exactly as browser `Number.isSafeInteger` does, while rejecting fractional, negative, and unsafe values; native regression coverage exercises all three cases. Runtime confirmation remains subject to the queued Godot CI job.

The browser implementation must remain intact while remaining feature, save-schema, combat, map, UI, and rendering parity is audited. Known remaining parity areas include full legacy-save compatibility and lossless round-tripping, chronicles visual/responsive parity and full browser-to-Godot interaction comparison, visual/UI parity, and paired scenario-level verification of NPC dialogue/services, map navigation, encounter lifecycle, and campaign/content progression. Faction bonuses are already wired into the native merchant pricing, incoming combat damage, encounter loot probability, and eligible world-event gold paths, with dedicated source-level regression coverage; their runtime confirmation remains subject to the unified Godot CI job. The native NPC layer also includes multiple village service/dialogue entries in addition to the wandering merchant, but complete browser-to-Godot scenario parity is not yet established. Native map marker handling now validates marker data and map-cell bounds, and supports mouse and screen-touch activation through one signal path; regression coverage exists for malformed markers, ragged/empty maps, and hit-target behavior, pending execution in Godot CI. Native chronicles now render as a styled archive: expandable chapter, lore-faction, and side-story panels; chapter entries use individual cards, long text wraps, and section controls expose expanded/collapsed state. Regression coverage checks the view wiring alongside catalog completeness. Browser-style responsive article-grid parity and runtime visual comparison are still unverified. These are verification and parity targets, not claims that each area is wholly absent.

## Verification

Browser and native validation now run through the single `.github/workflows/ci.yml` workflow. The browser checks run in `Verify (syntax + imports + smoke load)`; Godot project import, native regression scripts, and main-scene smoke boot run in `Validate native Godot project`. The separate `godot-ci.yml` validation workflow was removed to avoid duplicate CI pipelines; deployment and browser-baseline import workflows remain separate because they perform non-validation tasks.

Use the GitHub Actions workflow as the verification source of truth. Do not describe native tests, browser checks, or deployment as passing until the corresponding workflow run for the current commit SHA has completed successfully. A queued or in-progress run is not a pass.
